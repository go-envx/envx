Besides the [built-in secrets store](../secrets-store/), a value can refer to a secret held in an external provider. envx fetches it when it resolves the environment, so the secret never has to be copied into your workspace.

| Scheme | Provider | Needs |
| --- | --- | --- |
| `op://` | 1Password | The `op` CLI on `PATH`, and either `OP_SERVICE_ACCOUNT_TOKEN` set or an authenticated session |
| `bws://` | Bitwarden Secrets Manager | The `bws` CLI on `PATH` and `BWS_ACCESS_TOKEN` set |
| `passwordstate://` | Passwordstate | `PASSWORDSTATE_API_KEY` set |

## Providers

A provider is disabled until it is declared under [`secrets.providers`](../../configuration/schema/#providers) in `envx.yaml`. A value that uses the scheme of an undeclared provider passes through unchanged, and [`validate`](../../commands/validate/) warns about it.

References are written as `scheme://path`. A short form omits the project or list, and envx fills it in from the provider's per-environment mapping for the environment being resolved.

### 1Password

Enable the provider in `envx.yaml`:

```yaml
# envx.yaml
secrets:
  providers:
    op: {}
```

Then reference secrets with:

```text
op://<vault>/<item>/<field>
op://<vault>/<item>/<section>/<field>
```

Authenticate the `op` CLI with `OP_SERVICE_ACCOUNT_TOKEN`, with `op signin`, or through the 1Password desktop app integration. envx runs `op read` with only the host's base and `OP_*` variables.

### Bitwarden Secrets Manager

Enable the provider in `envx.yaml`:

```yaml
# envx.yaml
secrets:
  providers:
    bws:
      project:
        development: web-app-dev
        production: web-app-prod
```

Then reference secrets with:

```text
bws://<secret-id>
bws://<project-name>/<secret-name>
bws://<project-id>/<secret-name>
bws://<secret-name>
```

The short `bws://<secret-name>` form reads from the project that [`secrets.providers.bws.project`](../../configuration/schema/#bws) in `envx.yaml` maps to the current environment. envx authenticates with the `BWS_ACCESS_TOKEN` host variable. If a secret or project name matches more than one entry, the error lists their IDs so you can reference one directly.

### Passwordstate

Enable the provider in `envx.yaml`:

```yaml
# envx.yaml
secrets:
  providers:
    passwordstate:
      url: https://passwords.example.com
      list-id:
        development: 1988
        production: 1989
```

Then reference secrets with:

```text
passwordstate://<password-id>
passwordstate://<list-id>/<password-title>
passwordstate://<password-title>
passwordstate://<password-id>#<field-name>
passwordstate://<list-id>/<password-title>#<field-name>
passwordstate://<password-title>#<field-name>
```

The optional `#<field-name>` suffix selects the field to read, such as `passwordstate://1988/db-admin#UserName`. Without one, the provider's `field` defaults to `Password`. The short `<password-title>` form reads from the list that [`secrets.providers.passwordstate.list-id`](../../configuration/schema/#passwordstate) in `envx.yaml` maps to the current environment. The API key is read from the `PASSWORDSTATE_API_KEY` host variable.

## Escaping and special characters

A literal `#` in a path is written `%23`. In `bws` and `passwordstate` names and titles, `%2F` stands for a slash. An empty path, an empty path segment, or a control character is an invalid reference.
