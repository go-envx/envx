```sh
envx run <project> -- <command> [args...]
```

`run` executes a command with the environment variables resolved from a project's namespace chain. Everything after the `--` separator is the command to run and its arguments.

By default, existing OS environment variables take precedence over values from your files. Pass `--overload` to let file values win instead. Signals are forwarded transparently to the child process, and its exit code is propagated verbatim.

The [local env file](../../concepts/local-env/) is read by envx but is not inherited by the child. A value in it overrides a key a namespace declares, but a variable that only the file defines, such as `BWS_ACCESS_TOKEN` or `ENVX_PRIVATE_KEY_DEVELOPMENT`, is not passed to the command. To pass one on, declare the key in a namespace or export it in your shell.

By default an unresolved value aborts the run before the child starts, so the child never receives an unresolved reference as plaintext. Pass `--ignore-errors` to warn on each unresolved value, omit its key from the child environment, and start the child anyway.

## Arguments

| Argument | Description |
| --- | --- |
| `<project>` | The project whose environment is injected. |
| `<command> [args...]` | The command to run, after a `--` separator. |

## Examples

The examples below use the same `api` workspace, running `printenv` so you can see the injected values:

  <ExampleBox>
    <Fragment slot="manifest">
      ```yaml
      # envx.yaml
      environments:
        - development
        - production

      projects:
        api:
          includes:
            - db
      ```
    </Fragment>
    <Fragment slot="files">
      ```yaml
      # db.yaml
      db:
        host: # set per environment
        port: 5432
        pool_size: 10
      ```

      ```yaml
      # db.development.yaml
      db:
        host: localhost
      ```

      ```yaml
      # db.production.yaml
      db:
        host: prod.internal
        pool_size: 50
      ```
    </Fragment>
    <Fragment slot="commands">
      ```sh
      # development is the default env.
      envx run api -- printenv DB_HOST
      # localhost

      # Resolve a specific environment.
      envx run api --env production \
        -- printenv DB_HOST
      # prod.internal

      # An existing OS var wins by default.
      DB_HOST=os.local envx run api \
        -- printenv DB_HOST
      # os.local

      # --overload lets file values win.
      DB_HOST=os.local envx run api \
        --overload -- printenv DB_HOST
      # localhost
      ```
    </Fragment>
  </ExampleBox>

## Flags

| Flag | Environment variable | Description |
| --- | --- | --- |
| `--env`, `-E` | `ENVX_ENV` | Target environment to resolve. |
| `--overload` | `ENVX_OVERLOAD` | File values override existing OS env vars. |
| `--ignore-errors` | | Warn on unresolved values and omit them instead of aborting. |
| `--require-overlays` | `ENVX_REQUIRE_OVERLAYS` | Require every overlay file to exist. |
| `--prefix` | `ENVX_PREFIX` | Prefix prepended to every key. |
| `--suffix` | `ENVX_SUFFIX` | Suffix appended to every key. |
| `--delimiter` | `ENVX_DELIMITER` | String used to join list values. |
| `--reference-pattern` | `ENVX_REFERENCE_PATTERN` | Regex overriding the `{{VAR}}` reference syntax. |

Plus the [global flags](../overview/#global-flags). The setting flags map to [settings](../../configuration/schema/#settings-2) and override the values in `envx.yaml`.

## Exit codes

envx maps outcomes to conventional exit codes so `run` composes cleanly in scripts. See [Exit codes](../../concepts/exit-codes/) for the full table; a child that exits `7` makes envx exit `7`.
