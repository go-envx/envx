```sh
envx validate
```

`validate` resolves every project against every declared environment and reports the problems a workspace-wide gate should catch before deploy. It never materializes plaintext, because every reference is diagnosed through the masked dry-run path, and it never aborts on a single failure: every problem is collected and reported together.

Errors always fail the command. `--strict` also fails it on warnings, chiefly a private key that is absent in this context. That is normal on a developer laptop but a failure for a full-CI gate. A failed report exits `1`; see [Exit codes](../../concepts/exit-codes/).

## Checks

Every check has a code, a default severity, and a matching per-check flag. Each entry below lists the code as it appears in the [`validate` block](../../configuration/schema/#validate) of `envx.yaml` and its default severity. Checks fall into three groups by what they read, which is also their cost.

By default every check runs. Passing any per-check flag runs only the named checks and skips the cost of the rest. A pre-commit hook can select just the offline store checks and pay for no environment merge. Each flag is the kebab-case twin of its camelCase code, so `--secret-is-not-encrypted` selects the check configured by `validate.secretIsNotEncrypted`.

Severity itself is set only in `envx.yaml`, never on the command line.

### Store checks

Offline and instant. These read only `secrets.yaml` and the keys file.

- `secretIsNotEncrypted` (`error`): a stored value is left unencrypted.
- `secretAlgorithmMismatch` (`error`): a value is stored under an algorithm other than the configured one.
- `secretIsNotReferenced` (`error`): a stored value is not referenced by any environment.
- `publicKeyIsMissing` (`error`): a group has stored secrets but no public key.
- `privateKeyIsInvalid` (`error`): a group's private key is malformed or does not match its public key.
- `privateKeyIsUnavailable` (`warn`): a group has no private key available in this context.

### Provider checks

Offline. These read the external providers the merge references.

- `externalProviderUnavailable` (`error`): a declared external provider cannot be used.

### Resolution checks

These merge each project and environment, then diagnose every reference through the masked dry-run path.

- `secretReferenceNotFound` (`error`): a reference points to a value absent from the store.
- `invalidSecretReference` (`error`): a secret reference is malformed.
- `secretReferenceIsUnresolved` (`error`): a reference passed every store check yet failed to decrypt.
- `circularVariableReference` (`error`): variable substitution forms a cycle.
- `unresolvedVariableReference` (`error`): a substitution names an undefined variable.
- `propertyNotDeclaredInBase` (`off`): an overlay key is never declared in its namespace base file.
- `invalidExternalReference` (`error`): a reference for an enabled external provider is malformed.
- `externalProviderNotEnabled` (`warn`): a value uses the scheme of an undeclared external provider.
- `externalReferenceUnresolved` (`error`): the provider could not resolve an external reference.

## Output

The table has `SCOPE`, `KEY`, `STATUS`, and `MESSAGE` columns. `SCOPE` is `<project>/<environment>` for a reference finding, or `secrets` for a store-level finding. Error and warning counts print on stderr, and a clean report prints `no validation problems found`.

`--output json` prints a `summary` with `failed`, `errors`, and `warnings`, and a `findings` array whose entries have `severity`, `project`, `environment`, `key`, `code`, and `message`.

## Examples

```sh
# Run every check.
envx validate

# Fail on warnings too, for CI.
envx validate --strict

# Machine-readable output.
envx validate --output json

# A pre-commit hook: only offline store checks, no environment merge.
envx validate --secret-is-not-encrypted --public-key-is-missing
```

## Flags

| Flag | Environment variable | Description |
| --- | --- | --- |
| `--strict` | | Fail on warnings as well as errors. |
| `--output`, `-o` | | Output format: `table` (default) or `json`. |
| `--require-overlays` | `ENVX_REQUIRE_OVERLAYS` | Require every overlay file to exist. |
| `--prefix` | `ENVX_PREFIX` | Prefix prepended to every key. |
| `--suffix` | `ENVX_SUFFIX` | Suffix appended to every key. |
| `--delimiter` | `ENVX_DELIMITER` | String used to join list values. |
| `--overload` | `ENVX_OVERLOAD` | Prefer file values over host variables in `{{VAR}}` substitution. |
| `--reference-pattern` | `ENVX_REFERENCE_PATTERN` | Regex overriding the `{{VAR}}` reference syntax. |
| `--<check-code>` | | One flag per check, such as `--secret-is-not-encrypted`. Run only the named checks. |

Plus the [global flags](../overview/#global-flags). `validate` has no `--env` flag because it checks every declared environment.
